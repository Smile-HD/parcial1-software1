# Proposal: AI-Assisted UML Design Tool (Exam Demo)

## Intent

Deliver every required capability minimally working within the 2-week (max 4) exam deadline: collaborative UML editor, AI interpreter (text + voice), Spring Boot codegen, Enterprise Architect and photo importers, plus a generated offline backend with offline AI assistant. Strategy: demo mode — thinnest end-to-end slice, aggressive reuse, nothing from scratch.

## Scope

### In Scope — minimum-viable demo slice (exploration component map, min-viable column)

1. Editor: diagram-lib canvas; model CRUD + multiplicities; JSON persistence.
2. Collaboration: 2 users, one diagram, presence; naive conflict handling.
3. Text interpreter: constrained commands → model deltas; confirm-before-apply; refuses "generate me a design."
4. Voice: STT API → text → same interpreter pipeline.
5. Codegen: one template set → backend only (entities/repos/controllers); golden sample always buildable. Generates NO frontend.
6. EA importer: XMI 2.1 → classes/attrs/ops/associations; auto-layout; skip proprietary tagged values.
7. Photo importer: one multimodal call → JSON → model; clean photos; human review.
8. Offline backend: embedded/file persistence; CRUD with no network.
9. Offline assistant: local small model; scripted actions; canned fallback.
10. Mobile frontend (EXTERNAL — NOT generated by the tool): a separate minimum test client, built apart, that connects to the generated backend, runs a CRUD operation, and exercises the offline assistant — the way to prove the generated backend is functional.

### Out of Scope

Full UML conformance; undo/versioning; full CRDT/offline merge; multi-turn NLU; layered/incremental codegen; multi-version XMI/round-trip; robust photo recognition; offline-first sync/installers; RAG/agent assistant; microservices.

## Capabilities

### New Capabilities

- `diagram-editor`, `realtime-collaboration`, `ai-text-interpreter`, `voice-input`, `spring-codegen`, `ea-xmi-importer`, `photo-importer`, `offline-backend-artifact`, `offline-ai-assistant`, `mobile-test-client`

### Modified Capabilities

None (greenfield).

## Approach

Approved: hexagonal modular monolith around the canonical diagram-model IR (single source of truth); pure framework-agnostic core; swappable adapters; background workers for slow jobs. System B emitted from templates in a separate tree — templates are data, never runtime. The generated backend MUST be functional (golden sample always builds/runs offline); codegen optimized for speed; codegen emits the backend ONLY — no frontend. Build order: (1) editor + interpreter + codegen; (2) voice + collaboration; (3) photo + offline AI; (4) external mobile test client proving the generated backend (built apart, NOT generated). Workstreams: core IR/editor, AI interpreting, codegen + System B, importers, collaboration, external mobile test client, demo hardening. Stack deferred to design.

## Risks

| Risk | L | Mitigation |
|------|---|------------|
| Schedule (2–4 wks, fixed scope) | High | Enforce build order; stub late pieces |
| Photo → diagram accuracy | High | Multimodal API; clean photos; review |
| Offline assistant reliability | Med | Scripted actions + fallback |
| Live collab fragility | Med | Managed sync lib; rehearsed script |
| Interpreter misreads | Med | Structured schema; confirm-before-apply |
| Generated code won't compile | Med | Validated templates; golden sample |
| XMI variance | Med | Pin 2.1; real sample; Plan B .qea SQLite |
| Demo-day no internet | Med | Recorded fallback |
| Mobile test client time crunch | Med | Thin client; fallback = demo backend via web/REST |

## Rollback Plan

Per-capability degradation ladder — demo never breaks: AI fails → recorded video; collab unstable → scripted second user; photo import off → golden photo; XMI breaks → bundled sample; assistant fails → canned path; codegen breaks → pre-generated golden project; mobile test client fails → demo the backend via a web/REST client or recorded video. Last resort: stub + recorded rationale.

## Assumptions / Open Questions

Assumed: assistant = scripted actions; subset XMI mapping OK; embedded DB; Spanish voice; mobile test client = external, NOT generated, minimum client to prove the generated backend.
Open: team size/skills; rubric weighting; demo-day internet; mobile test client tech (web/PWA vs thin native).

## Success Criteria

- [ ] All 10 capabilities demoable end-to-end
- [ ] Golden backend builds, runs offline, assistant executes a scripted action
- [ ] Mobile test client (external) connects to the generated backend, runs a CRUD op, and exercises the offline assistant
- [ ] Real EA XMI sample imports
- [ ] Demo script rehearsed, every fallback verified
